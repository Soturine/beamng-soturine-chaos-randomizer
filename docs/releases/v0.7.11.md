# Soturine's Chaos Randomizer v0.7.11

Live Preview and Events UI **experimental prerelease** targeting BeamNG.drive
0.39.4.x, derived from the owner's v0.7.10 live session; see the
[root cause report](../testing/v0.7.11/ROOT_CAUSE_REPORT.md).

## Fixed

- **The formation preview follows its origin.** Markers move and turn with the
  player (or camera) instead of staying where they were calculated; Custom
  origins stay fixed and the player marker stays on the car.
- **The render hook stays light.** It no longer publishes the full application
  state from inside the render callback; preview changes reach the UI as a
  small Race update, and the full safety planner runs only when something
  actually changed.
- **The app shell cannot slide out of view.** The shell is no longer a scroll
  container, so focus changes can't push the header and tabs away, and a
  failure while applying state shows a "Reload panel" option instead of an
  empty app. The black-rectangle report is addressed structurally and awaits
  the owner retest.

## Changed

- Formation has one **Show preview / Hide preview** toggle. It works before
  generating opponents (estimated sizes) and updates when formation, origin,
  heading or spacing change. Position All stays separate and always plans from
  the current world.
- The generation staging preview is internal again; its origin settings remain
  under Advanced options as a technical option.
- Setup no longer shows an empty competitor card; origin labels are short with
  a one-line explanation.

## Validation

Automated validation: Passed.

Live BeamNG validation: Pending owner validation.

Live cases: **0 executed / 0 passed / 0 failed / 13 pending / 0 blocked**.

Contract tests cover anchor follow (translation, rotation, player marker,
Custom fixed), no planning, raycasts or UI emits inside the render hook, a
bounded Race diff from `onUpdate`, the Formation preview before generation,
independent preview and placement gates, the shell staying mounted through
preview updates, and the root recovery panel. They do not prove visible
markers or AppHost pixels; see [live results](../testing/v0.7.11/LIVE_RESULTS.md).

## Known limitations

- All 13 live cases require owner execution with the exact downloaded ZIP.
- The black-rectangle cause was not reproduced outside the game; its fix is
  structural until the owner retest confirms it.
- D3D12, Vulkan, controller/UINav, UI scale/safe zones and live performance
  remain unvalidated.

Only the deterministic ZIP, `.zip.sha256` and manifest are supported assets.
GitHub source archives are not mod packages.
